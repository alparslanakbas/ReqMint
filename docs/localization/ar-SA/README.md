# دليل البدء في ReqMint

> حالة المحتوى: مسودة عربية تحتاج إلى مراجعة متحدث أصلي قبل النشر العام.

توجد خطوات المراجعة وإثبات الاعتماد في [دليل المراجعة الأصلية](NATIVE_REVIEW.md). لا يعني وجود هذا الدليل أن الترجمة معتمدة.

ReqMint أداة مكتبية محلية أولاً لإنشاء طلبات HTTP واختبارها وتنظيمها. لا تحتاج معاينة Community إلى حساب ReqMint، ولا ترفع مساحات العمل إلى خدمة مزامنة تابعة لـ ReqMint.

## إرسال أول طلب بأمان

1. افتح ReqMint واختر **بدء الدليل المحلي** من شاشة الترحيب.
2. ينشئ التطبيق مساحة عمل تعليمية مؤقتة وواجهة API محلية على جهازك.
3. افتح طلب الترحيب واضغط **إرسال**.
4. افحص رمز الحالة والرؤوس ومحتوى الاستجابة.
5. شغّل المجموعة التعليمية لمشاهدة عمليات التحقق والنتائج المتكررة.
6. أنهِ الجلسة التعليمية عندما تنتهي؛ لا تُستخدم أي واجهة API تجريبية خارجية.

## إنشاء مساحة عمل حقيقية

1. اختر مجلداً محلياً جديداً أو موجوداً.
2. أنشئ مجموعة للطلبات المرتبطة بالخدمة نفسها.
3. أضف بيئة لقيم مثل عنوان الخدمة الأساسي.
4. ضع القيم الحساسة في حقول الأسرار المخصصة لها، ولا تضفها مباشرة إلى الملفات المشتركة.
5. احفظ الطلب ثم أرسله وتحقق من الاستجابة.

## العمل مع Git

مساحات عمل ReqMint ملفات واضحة يمكن مراجعتها باستخدام Git. يعرض التطبيق التغييرات والفروقات قبل أي إجراء صريح. لا ينفذ ReqMint عمليات إعداد أو التزام أو تحديث أو دفع صامتة.

راجع الملفات دائماً قبل مشاركتها. يفحص ReqMint الملفات التي يديرها ضمن مسارات النشر المدعومة، لكنك تظل مسؤولاً عن الوجهات والمستودعات والبيانات التي تختارها.

## اتجاه النصوص التقنية

تظهر واجهة التطبيق العربية من اليمين إلى اليسار. وتبقى عناوين URL وطرق HTTP والرؤوس وJSON ومفاتيح البيئة ومسارات الملفات ومخرجات Git من اليسار إلى اليمين حتى تظل قابلة للقراءة والنسخ بدقة.
